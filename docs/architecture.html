Factory Inventory Management System

Architecture overview: system layout, tech stack, and data flow

System Architecture

A three-tier demo application. There is no database: the backend loads JSON files into memory at startup and serves them over REST.

  • FastAPI for the REST API and automatic /docs
  • Pydantic 2 for response validation

Data Flow

How a filter change on the Dashboard becomes updated numbers and charts.

  1. User changes a filter FilterBar writes to the singleton refs in useFilters (Time Period, Warehouse, Category, Order Status). Because the refs live at module scope, every view shares the same state.
  2. View watches the filters The view's watch([selectedPeriod, selectedLocation, ...]) fires and calls getCurrentFilters(), which maps the selections to warehouse, category, status, and month.
  3. API client builds the request api.js drops any filter set to all and sends the rest as query parameters. The Dashboard calls summary, orders, inventory, and backlog in parallel.
  4. FastAPI filters in memory apply_filters() matches warehouse exactly and category and status case-insensitively. filter_by_month() accepts a month (2025-09) or a quarter (Q3-2025) and matches on order_date.
  5. Pydantic validates the response Each endpoint declares a response_model, so rows are checked against the model before being serialized to JSON. The summary and report endpoints build their numbers with plain Python aggregation.
  6. Raw data lands in refs The view stores results in refs such as allOrders and inventoryItems.
  7. Computed properties derive the display Chart series, status counts, top products, and revenue-goal progress are computed() values built from those refs, so the UI re-renders automatically.

Known Gaps

Frontend calls endpoints the backend does not implement.

api.js defines client methods for tasks and purchase orders, but server/main.py has no matching routes. Checked against the running server, each of these returns 404:

Client callRequestResult
getTasks / createTask / toggleTask / deleteTask/api/tasks404
createPurchaseOrder / getPurchaseOrderByBacklogItem/api/purchase-orders404

The backend defines PurchaseOrder models and reads purchase_orders.json (currently an empty list) to compute has_purchase_order, but never exposes create or read routes. The Reports view also bypasses api.js and calls axios directly with a hard-coded base URL.
